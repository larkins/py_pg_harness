# Peristyle Harness

Postgres-backed agent memory with a single Flask chat surface and
multi-agent isolation via per-schema Postgres. One process, one chat
surface, one shared users table — and a memory engine where every
memory is a row you can vector-search, trigram-search and pin.

The harness is the whole runtime: an agent loop that calls an LLM,
a `MemoryAPI` that is the only thing allowed to touch SQL, a tool
registry, a bootstrap loader that injects the agent's identity files
into every prompt, and a web UI to drive it from.

---

## Install

```bash
git clone https://github.com/peristyle-ai/py_pg_harness.git
cd harness
cp install.config.example.yaml install.config.yaml
$EDITOR install.config.yaml
tools/install.sh --config install.config.yaml --dry-run    # see the plan
tools/install.sh --config install.config.yaml              # do it
```

The installer is **non-interactive** and **idempotent** — there are no
prompts, and running it twice is a no-op the second time. Always run
the `--dry-run` first: it prints every command it would run, the
roles it would create, and the paths it would write, without touching
anything.

`install.config.yaml` is the only file you edit. It has five sections:

| Section | What it decides |
|---|---|
| `install` | The Unix account to run as (`operator_user`), where to clone (`install_dir`), the repo URL |
| `database` | Which Postgres database, and the two roles (operator + runtime) |
| `first_admin` | The first human account in `public.users` |
| `agent` | The first agent's name, display name and emoji |
| `llm` / `embedding` | Which model adapter, which model, which embedding endpoint |

Secrets you leave empty (`runtime_password`, `operator_password`,
`first_admin.password`, `llm.api_key`) are generated by the installer
and printed **once**. The first admin's password is never written to a
file — it is generated and shown at the end of the install.

### Database modes

`database.mode` has two values, and the choice is the single most
important line in the config:

| Mode | What it means |
|---|---|
| `fresh` | The installer creates the database, the extensions and the roles. Use it for a standalone harness on its own Postgres instance. |
| `existing` | The database already exists and may be shared with other projects. The installer attaches to it, creates only what is missing, and refuses to continue if what it finds is incompatible. |

### The `public.users` rule

**The harness owns and creates `public.users`.** It is the one
application-user table the whole deployment shares. Every other
project in the same database — mail, webmail, accounts, projects —
only ever *verifies* it. A second, divergent users table is the bug
this design exists to prevent: two projects that each create their own
`users` table mean a user has two identities and neither project can
authenticate the other.

- The canonical DDL lives in one place: [`db/public_users.sql`](./db/public_users.sql),
  pinned by checksum in `db/public_users.sha256`.
- The harness applies it through
  [`migrations/015_canonical_users.sql`](./migrations/015_canonical_users.sql),
  which pulls the canonical file in and only ever *adds* columns.
- Other projects run the preflight,
  [`db/preflight_users.sql`](./db/preflight_users.sql), which
  **verifies** — it never creates. If the table is missing or
  incompatible it raises and the install fails fast.
- `tools/check_public_users_version.sh` fails if a vendored copy has
  drifted from the pinned checksum.

So: in `existing` mode the installer checks whether `public.users` is
present. Present → it runs the preflight and refuses to continue on a
mismatch. Absent → the harness creates it, because it owns it. In
`fresh` mode it simply creates it.

### After the install

```bash
systemctl --user status harness.service
curl -s http://127.0.0.1:5010/health
```

The chat UI is at `/`. The JSON API is at `/api/v1/*` — `/api/v1/chat`,
`/api/v1/conversations`, `/api/v1/memories`, `/api/v1/auth/login`.

## The default agent

The installer renders a first agent from
[`agent_template/`](./agent_template/) into
`pie/<agent_name>/identity/`. The templates carry `{{PLACEHOLDER}}`
markers (`{{AGENT_NAME}}`, `{{USER_NAME}}`, `{{INSTALL_DIR}}`,
`{{DB_NAME}}`, …) that the installer substitutes from your
`install.config.yaml`. See
[`agent_template/README.md`](./agent_template/README.md) for the full
placeholder list and the byte caps.

Every identity file has a hard byte cap, enforced at boot — an
over-cap file is a **boot failure**, not a silent truncation:

| File | Cap |
|---|---|
| `SOUL.md` | 8,000 bytes |
| `USER.md` | 4,000 bytes |
| `AGENTS.md` | 24,000 bytes |
| `IDENTITY.md` | 8,000 bytes |

### Skills that ship

| Skill | What it does |
|---|---|
| `create_timer` | Schedules a recurring wake-up of an agent's main session via a `systemd --user` timer + service that POSTs to `/api/v1/internal/timer`. This is how a promise to "follow up in 20 minutes" survives context compaction. |
| `openclaw_migration` | Ingests an agent's memory from a legacy OpenClaw workspace (`MEMORY.md` + daily notes) into the harness's `memories` table, and copies its identity files + skills into the per-agent directory. |

**`local-email` deliberately does NOT ship.** It is a local
mail-server skill with deployment-specific credentials and TLS
material baked into its assumptions. If you want it, copy it in
afterwards from your own source tree and adapt it to your install:

```bash
cp -r /path/to/local-email skills/local-email
```

Nothing in the harness depends on it.

## Configuration

`config.yaml` is committed and holds no secrets; every value is a
`${VAR}` reference into `.env`. The installer writes both files
(`.env` mode 600, gitignored).

### The keys that matter

| Key | Meaning |
|---|---|
| `app.default_agent` | Which agent serves `/` when no agent is pinned |
| `app.agents` | The roster of installed agents (one Postgres schema each) |
| `app.pie_root` | Where the per-agent directories live |
| `db.url` | The runtime role's connection string |
| `db.operator_role` | The role allowed to run DDL (migrations) |
| `db.runtime_role` | The role the app connects as — DML only, no `CREATE`/`DROP`/`ALTER` |
| `db.database` | The database name |
| `llm.adapter` | Which adapter module loads (`app/agent/llm/<adapter>.py`) |
| `llm.per_agent` | Per-agent LLM blocks; each **replaces** the global block wholesale |
| `embedding.base_url` / `.model` / `.dimensions` | The embedding endpoint. `dimensions` must match the pgvector column (`halfvec(1024)`) or retrieval fails silently |
| `memory.top_k` / `.vector_limit` / `.trigram_limit` | Hybrid retrieval sizes (vector + trigram, fused by RRF) |
| `memory.permanent.max_tokens` | The budget for pinned memory injected into every prompt |
| `agent.max_tool_iterations` | Outer cap on the tool-use loop |
| `agent.max_searches_per_turn` | Inner cap on memory searches |
| `bootstrap.files` | Which identity files to load and each one's byte cap |
| `bootstrap.behavior_on_overflow` | `fail` (recommended) or `truncate` |
| `prompt.pressure_enabled` / `.pressure_threshold` | Warn the agent when an identity file nears its cap |
| `reverie.*` | The nightly self-cleanup turn |
| `security.rate_limit.*` | Per-route request caps |

### The environment variables

Copy `.env.example` to `.env` and fill it in. The ones you must set:

```bash
# Flask
HARNESS_SECRET_KEY=          # python3 -c "import secrets; print(secrets.token_urlsafe(48))"
HARNESS_BIND=127.0.0.1:5010

# Postgres
DATABASE_URL=postgresql://<runtime_role>:<password>@localhost:5432/<db_name>
APP_DB_OPERATOR_ROLE=<operator_role>
APP_DB_RUNTIME_ROLE=<runtime_role>
HARNESS_DB=<db_name>

# Agent
HARNESS_DEFAULT_AGENT=<agent_name>

# LLM
LLM_ADAPTER=minimax_m31_flash
LLM_API_KEY=<key>
LLM_BASE_URL=https://api.minimax.io/anthropic
LLM_MODEL=MiniMax-M3.1-Flash

# Embeddings — the dimension MUST match the pgvector column
EMBEDDING_BASE_URL=http://127.0.0.1:8080/v1
EMBEDDING_MODEL=Qwen/Qwen3-Embedding-4B
EMBEDDING_DIMENSIONS=1024

# Internal token — the create_timer skill's POSTs authenticate with it
HARNESS_INTERNAL_TOKEN=<32+ random chars>
```

`.env` must be mode 600; the app refuses to start otherwise.

## Running the tests

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt

pytest tests/ -v
```

The unit tests do not need a live model or a live database. A few
files under `tests/` are **manual** harnesses rather than pytest
suites — they drive the real LLM endpoint and print a report, so run
them by hand when you change an adapter:

```bash
set -a; . ./.env; set +a
python tests/tests_stream_parity.py       # SSE path vs buffered path
python tests/tests_toolloop_stream.py     # full tool-call round trip
python tests/tests_delta_forwarding.py    # delta emission + reassembly
python tests/tests_prompt_pressure.py     # prompt-pressure warnings
python tests/reproduce_turn.py "<prompt>" [agent]
```

The security audit tests also run in a live mode against a running
instance:

```bash
pytest tests/test_security.py -v
HARNESS_RUN_LIVE_TESTS=1 pytest tests/test_security.py
```

## Design principles

1. **Postgres is the source of truth.** Every memory is a row. No
   markdown roundtrips, no daily-note file churn.
2. **Memory is a tool, not a context-dump.** The model gets a
   `memory_recall` tool and decides when to use it. The loop never
   auto-injects retrieved memories.
3. **Memory access is mediated.** The loop calls `MemoryAPI`; it
   never writes SQL. Schema isolation, parameter validation, rate
   limits and audit are enforced at that one boundary.
4. **Multi-agent is a Postgres concept, not a process concept.**
   Adding an agent is `CREATE SCHEMA <name>` plus a per-agent schema
   installer — not a new Unix user, a new systemd unit or a new tunnel.
5. **Hybrid retrieval by default.** Vector (`halfvec`) *and* trigram
   (`pg_trgm`) *and* full-text, fused with Reciprocal Rank Fusion.
   Both indexes are required, not optional.
6. **One chat surface.** HTML at `/`, JSON at `/api/v1/chat`. No second
   channel.
7. **Per-file caps, never a collective cap.** A collective cap makes
   files silently drop each other from the prompt and turns a bug into
   a mystery. Per-file caps make overflow loud and name the file.

The full spec — the domain model, the write and retrieval paths, the
adapter contract, the tool framework, the deployment procedure — is in
[`REQUIREMENTS_AND_SPECIFICATIONS.md`](./REQUIREMENTS_AND_SPECIFICATIONS.md).
